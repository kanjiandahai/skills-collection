# tdd

严格走 **红 → 绿 → 重构**，用测试锁定行为后再堆实现。

## 何时用

- 新功能或修 bug，且行为可断言
- 用户明确要求 TDD / 先测后码
- 回归风险高的核心逻辑

## 工作流

1. **写一个失败测试**，描述一个最小行为；跑测试，确认是「失败」而非「报错配置坏了」。
2. **写最少代码**让该测试通过；不顺便加功能。
3. **重构**：在测试全绿前提下清理重复与命名。
4. 重复以上，直到需求切片做完。
5. 提交前跑相关测试套件；测试名应读起来像规格说明。

## 规则

- 没有失败测试就不动产品代码（探索性 spike 需隔离，之后补测或扔掉）
- 一次只推进一个行为切片
- 测试测行为与边界，不测私有实现细节
- 外部 I/O 用替换件/夹具，保持单元测试快而稳

## 成功标准

- 每个行为都有先红后绿的历史可循（至少本地跑通）
- 套件稳定；实现可在测试保护下重构
