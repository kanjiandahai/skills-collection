# pptx-deck

面向助手的 **演示文稿制作规范**：先定受众与故事线，再落可编辑的 `.pptx`，避免把文档粘成墙字。

## 何时用

- 新建或大幅改写 `.pptx` / 幻灯片 / 路演稿
- 把大纲、纪要、方案收成可上台讲的 deck
- 需要统一版式、少字大图、一页一观点

只要流程图逻辑、不要幻灯片时，用 `flowchart-mermaid`。图要进 PPT 时：逻辑用 Mermaid 定稿，再导出 PNG/SVG 插入，或在幻灯片里用少量子形状重画关键路径。

## 开工前确认（缺一就问一句）

1. **受众**（老板 / 客户 / 同学 / 内部评审）
2. **时长与页数上限**（未说则默认 8–12 页、约 10 分钟）
3. **语气**（正式商务 / 轻松 / 技术深度）
4. **交付物**：只要 `.pptx`，还是也要讲稿备注

## 故事线模板

典型顺序（可裁剪）：

1. 封面：标题 + 副标题 + 日期/作者
2. 问题或机会（1 页说清「为什么现在」）
3. 结论先行（可选，汇报类强烈建议）
4. 证据 / 方案步骤（每页一个论点）
5. 对比、数据或案例（图表优于长表）
6. 风险与下一步
7. 致谢 / Q&A

先写 **一页一行的大纲**，用户点头后再铺版式。

## 视觉与文案规则

- **一页一观点**；标题是结论句，不是主题词堆砌
- 正文 **短句 + 要点**；单页可见字尽量少，细节进备注或附录
- 字号：标题 ≥ 28pt，正文 ≥ 18pt；对比度要高（深底浅字或浅底深字）
- 留白：边距充足，避免贴边与随意装饰线
- 配色：主色 1 + 强调色 1 + 中性灰；全稿一致
- 图表：只保留与论点直接相关的系列；坐标轴与单位写清
- 中文稿注意断行：避免标题在「的/和」处尴尬折行

## 技术路径（按环境选）

| 任务 | 推荐做法 |
|------|----------|
| **新建** deck | 用 `pptxgenjs`（Node）或 `python-pptx` 写脚本生成，便于复跑与改稿 |
| **小改** 已有 pptx | 能 API 改版式就改；复杂母版/占位符时解包 OOXML 需格外小心关系文件 |
| **读内容** | 抽取每页标题与正文做 diff；改完再抽一次核对 |
| **流程图进页** | 先 Mermaid 定稿 → 导出 SVG/PNG 嵌入；需要同事在 PPT 里拖拽改节点时，改为少量原生形状 |

生成脚本应参数化：标题、主色、页边距、字体（中文可用系统已有字体，如 `Microsoft YaHei` / `PingFang SC` / `Noto Sans CJK`，按运行环境探测，缺字就降级并说明）。

## 生成检查清单（交稿前）

- [ ] 每页标题能单独读懂论点
- [ ] 无大段粘贴文；要点 ≤ 5 条/页（多数情况）
- [ ] 全稿字体、边距、主色一致
- [ ] 封面与末页信息完整；页码如需要已加
- [ ] 打开文件抽查：无叠字、裁切、低对比
- [ ] 若用户要讲：备注里有口播提纲，而非把备注当正文堆满

## 反模式

- 把 Word/长文直接拆段进幻灯片
- 一页塞多条无关结论
- 装饰性剪贴画、彩虹渐变、3D 无意义效果
- 未确认受众就做超长技术附录当主线

## 成功标准

- 产出可打开的 `.pptx`
- 页数与约定时长匹配，故事线完整
- 视觉统一、上台可读；用户无需先「清版」才能用
