# frontend-design

像设计工作室一样：**先为这个题材定方向，再写代码**；大胆用在一处，其余克制。

## 何时用

- 从零做页面/组件视觉
- 现有 UI 太「模板感」，要换气质
- 需要配色、字体、布局与文案语气一致

## 工作流

1. **锚定题材**：产品是什么、给谁用、第一眼要传递什么；信息不够就先提案再确认。
2. **短设计计划**（动工前）：
   - 色：4–6 个命名色值
   - 字：1–2 个字体家族及用途
   - 布局：一句话概念 + 简易线框
   - 原则：本页独特在哪里
3. 对照计划自检：是否又滑向「奶油底+衬线+陶土强调色」「黑底霓虹」「无差别圆角卡片墙」等通用默认；是则改掉无关题材的部分。
4. 再实现代码；注意选择器不要互相抵消；完成后用截图做一轮「少一件饰品」式删减。

## 原则摘要

- Hero 要选真正代表题材的形式，不是默认「大数字+渐变」
- 字体承载性格；行长通常 < 80 字符
- 结构元素（分割线、编号）要传达信息，不为装饰；编号仅用于真实序列
- 动效克制：一次精心编排好过处处 fade-up
- 文案是界面的一部分：主动作命名一致、错误给出修复方向

## 成功标准

- 看得出与题材相关的明确立场，而不是通用 SaaS 皮
- 移动端可用、对比度可读；焦点与减少动效等基本可访问性未崩
