# grill-me

用 **连续追问** 把含糊计划逼成可执行设计：一次只问一个问题，并给出你的推荐答案。

## 何时用

- 方案还在脑袋里，需要被「烤」清楚
- 架构/产品/流程决策分叉多，怕漏依赖
- 用户明确说「grill me / 拷问我」

## 工作流

1. 用一两句话复述你听到的目标与约束，标出最大不确定点。
2. **一次只问一个问题**；每个问题附上 **你的推荐选项**（可简短说明理由）。
3. 沿决策树往下走：先决问题先问；能靠读代码/仓库回答的，去查，不要干问。
4. 用户回答后，更新「已锁定决策」列表，再问下一枝。
5. 关键分叉都收敛后，输出一页 **共识摘要**：目标、非目标、关键决策、开放风险、建议下一步。

## 提问质量

- 优先问会改变设计形状的问题（边界、成功标准、约束、失败模式）
- 避免一次性问卷；禁止把五个问题堆在一条消息里
- 发现前后矛盾时明确指出来，请用户二选一

## 成功标准

- 决策依赖顺序清楚，无未关闭的关键分叉
- 共识摘要可直接拿去开工或开 PR 描述
